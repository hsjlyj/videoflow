# Toonflow 私有快照版（中文说明）

这是一个基于上游 Toonflow 当前工作目录导出的私有快照仓库，用于保存本次实际运行中的可用版本与定制修改。

本仓库特点：
- 纯中文说明
- 包含当前工作目录中的已跟踪文件与未跟踪新增文件（已排除临时调试脚本）
- 重点保留本次修复过的图片生成、多参考图分镜生成与运行时工具改动
- 适合后续继续迭代、对比、回滚与私有部署

## 这个仓库是什么

它不是上游官方只读镜像，而是“当前正在运行并已实际验证过”的私有版本快照。

导出来源：
- 上游来源仓库：`https://github.com/HBAI-Ltd/Toonflow-app.git`
- 导出时上游 HEAD：`af1d1cb`
- 导出方式：从远端 `/opt/Toonflow-app` 工作目录打包当前 tracked + untracked 文件（排除临时调试脚本）

## 本次保留的重点改动

### 1. 图片生成支持多参考图
涉及文件：
- `data/vendor/bull.ts`
- `src/routes/setting/vendorConfig/modelTest/imageTest.ts`
- `src/routes/assetsGenerate/generateAssets.ts`
- `src/routes/assetsGenerate/batchGenerateImageAssets.ts`

主要内容：
- 图片测试接口支持 `imageBase64List`
- 单张资产生成支持 `base64List`
- 批量资产生成支持每项 `base64List`
- `bull` 供应商真正消费 `referenceList`，而不是只按纯文本生图

### 2. 分镜面板多参考图生成修复
涉及文件：
- `src/routes/production/storyboard/batchGenerateImage.ts`
- `data/vendor/bull.ts`
- `src/utils.ts`
- `src/utils/vm.ts`

主要内容：
- 分镜参考图从 storyboard 关联资产真实传递给模型
- 多参考图先压缩，再按类型组织
- 角色 / 场景 / 道具分组喂给模型
- vendor 多参考图请求支持 524 / 502 / timeout 重试
- 修复运行时工具导出与拼图返回格式问题

### 3. 分镜多参考图效果增强
在分镜参考图组织上继续做了几层增强：

#### 角色参考图
- 人物卡式拼图
- 独立卡片留白
- 角色编号标题（角色1、角色2……）
- 主角色优先，对手次之，次要角色靠后

#### 场景参考图
- 全景优先拼图
- 主场景 / 次场景顺序
- 更强调空间结构、透视与主色调

#### 道具参考图
- 白底特写优先
- 关键道具 / 次道具顺序
- 更强调轮廓、材质、颜色

#### Prompt 结构增强
- 把原始 `@图N` 关系改写为结构化中文参考摘要
- 提示模型按人 / 景 / 物分别对齐参考图

## 目录说明

- `src/`：核心服务端与前端源码
- `data/vendor/`：模型供应商适配逻辑
- `data/web/`：构建后的前端静态文件
- `scripts/`：构建与辅助脚本
- `docs/`：原项目文档与资源
- `pm2.json`：当前快照附带的 PM2 启动配置

## 建议使用方式

### 本地开发
1. 安装依赖
2. 配置所需模型供应商
3. 运行开发模式或构建模式
4. 在设置中心验证文本 / 图像 / 视频模型

参考命令：

```bash
yarn install
yarn build
yarn start
```

### PM2 运行
如果你希望按当前快照方式运行：

```bash
pm2 start pm2.json
pm2 status
```

## 当前版本更适合什么

这个私有快照特别适合下面几类工作：
- 保存一个已经跑通过的 Toonflow 定制版本
- 继续优化分镜多参考图生成效果
- 对比上游更新与本地私有改动
- 做私有部署、PM2 运行或服务器迁移

## 注意事项

1. 这是工作目录快照，不是“仅包含干净 diff”的最小补丁仓库。
2. 仓库中可能同时包含：
   - 上游已有内容
   - 当前工作目录改动
   - 已构建静态文件
3. 如果后续要长期维护，建议再拆分成：
   - 上游同步分支
   - 私有定制分支
   - 仅部署产物分支（可选）
